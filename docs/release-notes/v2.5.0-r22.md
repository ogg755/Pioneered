# v2.5.0-r22 — sleeker buttons, one-tap USB, snappier waveform and library

<!-- debs: rebuild -->

New Mixxx build + skin. A look-and-feel pass over the buttons, plus a
responsiveness pass over the paths the earlier patches put on the hot loop.

- **Buttons look like hardware, not rectangles** — the radius scale is
  normalised to three tiers (3 px small controls, 4 px touch targets, 8 px
  panels and banners) instead of the ad-hoc 2/3/4/5/6/8 px mix, buttons that
  have a fill get a subtle top-down gradient so they read as moulded, backlit
  CDJ buttons, and the scattered greys collapse into one border ladder. The
  inactive tab chrome is dimmed so the active yellow tab carries the strip.
  The Pioneer palette, the tab strip's proportions and the CDJ notch on the
  waveform header are unchanged — this is `style.qss` only, no XML, so
  nothing moves.
- **The three tabs are actually symmetric now** — OVERVIEW / BROWSE / SEARCH
  had two separate problems. Their horizontal margin was written `10%`, and
  Qt Style Sheets have no percentage length, so it silently evaluated to zero
  and the gaps between tabs were only ever whatever Qt did with leftover
  space. And the cog added in r21 had no counterweight, so all the slack in
  the strip sat on the right and pushed the trio left of centre. The margin
  is now a real pixel value, a fixed spacer the exact width of the cog
  balances the left end, and the tabs divide everything between them three
  ways — identical widths and identical gutters at any window size.

- **Every button acknowledges a tap** — until now only the on-screen keyboard
  had a pressed face, so tapping USB A, LOAD, a tab or a settings button gave
  no feedback at all until the action it triggered landed. That reads as lag
  even when nothing is slow. All of them now light up on touch-down.
  The USB, LOAD and sampler pressed faces are deliberately scoped to the idle
  state: a plain pressed rule stays active for a whole hold and would sit on
  top of the eject and hold-to-restart flashes, hiding the very feedback that
  tells you how long you have held.
- **USB A/B works on the first press** (`usb-browse-one-tap.patch`, patch 14).
  The rekordbox device list only refreshes on activation, so a press on a
  freshly inserted stick used to kick off the device scan, return
  empty-handed and do nothing visible — you had to press again. The press is
  now remembered and completes itself the moment the scan reports the stick.
  A new press, an eject or a root restore supersedes it, and it gives up
  after 10 s if the stick never appears. This was the most visible dead spot
  in the console: the first interaction after boot looked broken.
- **Taps during a database parse are no longer thrown away** — activating a
  device while a previous PDB parse was still running was silently discarded,
  which on a slow stick is seconds of UI that ignores you. The activation is
  queued and re-dispatched when the parse finishes.
- **Waveform, library and watchdog cost down** (`perf-render-repaint.patch`,
  patch 13 — no behaviour change):
  * The bar-marker renderer reallocated a buffer on *every frame*, issued two
    separate polygon fills per downbeat, and recomputed a beat index per beat
    that could degrade to a quadratic walk on long tracks. Now: reused
    buffers, one batched fill, index hoisted out of the loop.
  * The key traffic light invalidated every cell of every track model on
    every deck play/pause — continuously during a mix, over playlists that
    can run to thousands of rows. Only the Key column is repainted now.
  * The key text was parsed once per Key cell per repaint, twice over. Now
    memoized.
  * Resizing the library re-derived and re-applied the row height, font and
    all four column widths from scratch on every resize event, each one
    relayouting the header and repainting the viewport. Now skipped when the
    numbers have not actually moved.
  * The controller reconnect watchdog rescanned every USB MIDI and HID device
    every 5 s *forever* when a controller was enabled in the preferences but
    unplugged — a recurring hitch and constant background CPU for a device
    that may never come back. It now backs off to a 60 s ceiling, while the
    first few attempts stay at 5 s so replugging still reconnects promptly.

## Install (on the Pi)

```
sudo ./update-pioneered.sh
```

## Field checks

1. Tabs, LOAD, USB A/B, sampler pads and the settings buttons all have a
   visible pressed face — press and hold one and it changes *before* you let
   go. (If nothing changes on any of them, Qt is not delivering the pressed
   state to these widgets and only that part of the restyle is inert; the
   rest of the look is unaffected.)
2. The active tab still reads clearly against the dimmed inactive ones, and
   OVERVIEW / BROWSE / SEARCH are the same width as each other with even gaps,
   sitting centred rather than pushed left by the cog.
3. The notched corner on the waveform info header is unchanged.
4. Hold-to-eject on USB A/B: banner at 5 s, force at 10 s, with the
   accelerating red/white flash intact — the flash must not be replaced by a
   solid pressed colour for the duration of the hold.
5. Hold LOAD 1 / LOAD 2 for 7 s: the white blink accelerates as in r21 and
   Mixxx relaunches. Short taps still load the selected track.
6. Insert a stick, then tap USB A **once**: its playlists open without a
   second tap. Do the same for USB B.
7. Tap USB A repeatedly while a big stick is still parsing: the last tap is
   honoured when the parse finishes rather than being dropped.
8. Play both decks and scroll a long playlist: the Key traffic lights stay
   correct and scrolling stays smooth.
9. Unplug the DDJ-400 and leave it out: the log no longer shows a controller
   rescan every 5 s indefinitely. Plug it back in — it still reconnects on
   its own without a trip to the preferences.
