# v2.5.0-r19.1 — USB LOCKED banner no longer cancels the force-eject hold

Skin-only fix. The three debs are byte-identical to r18 (re-attached so the
one-shot updater finds them); only the Pioneered skin changed.

- **Force eject was impossible** — at the 5 s tier of a hold on a locked
  stick, the "PLAYING FROM USB — PAUSE TO EJECT, KEEP HOLDING TO FORCE"
  banner appeared as an invisible full-screen overlay covering the held USB
  button. Qt then sent the button a Leave event, and Mixxx's WPushButton
  fakes a mouse release on Leave, so the hold was cancelled the instant the
  banner explained how to force. The popup overlays are now sized to the
  banner itself (480×90, still centered), so they never cover the USB
  buttons and the hold runs on to the 10 s force tier.
- Side benefit: while a banner is visible (2 s), the rest of the touchscreen
  stays interactive — the full-screen overlay used to swallow every touch.

## Install (on the Pi)

```
sudo ./update-pioneered.sh            # latest release
sudo ./update-pioneered.sh v2.5.0-r19.1 # this release explicitly
```

apt will report the mixxx packages as already at r18.1 — that is expected;
the skin install and reboot are what deliver this fix.
