# v2.5.0-r23 — waveform height no longer follows the gain knob

<!-- debs: rebuild -->

New Mixxx build. One targeted change to how the waveform is drawn.

- **The waveform is drawn at a fixed height** (`xdj-behavior.patch`, patch 3).
  Until now the channel **gain/trim** knob stretched the on-screen waveform
  taller as you turned it up and squashed it shorter as you turned it down
  (replaygain normalisation did the same on load), because the renderer scaled
  the wave by `total_gain` — the mix level, not the track. On Pioneer gear the
  waveform reflects the *track's own content* and stays put regardless of the
  channel level, so you read the track the same way whether the fader trim is
  parked or pushed. `WaveformWidgetRenderer::onPreRender` now pins the visual
  amplitude to a constant instead of reading `total_gain`. The audio path is
  untouched — `total_gain` still sets the actual level; only the drawing is
  decoupled. This completes the waveform-vs-mix decoupling started in r9, which
  already stopped the EQ knobs and kill switches from scaling the RGB bands.

## Install (on the Pi)

```
sudo ./update-pioneered.sh
```

## Field checks

1. Load a track, then sweep the channel **gain/trim** knob (or the DDJ-400
   TRIM) from min to max: the waveform height must not change — it stays at a
   fixed scale the whole way. (Before r23 it grew and shrank with the knob.)
2. The audio still responds to the knob normally — turning trim up is louder,
   down is quieter; only the *drawing* is fixed.
3. Load a quiet track and a loud track with replaygain enabled: both draw at
   the same reference scale rather than one being visibly taller than the other
   purely from normalisation.
4. EQ knobs and kill switches still do **not** scale the RGB bands (unchanged
   from r9) — a closed LOW still shows the track has bass at that point.
