# v2.5.0-r21 — settings menu, hold-to-restart, louder headphone cue

<!-- debs: rebuild -->

New Mixxx build + skin. The XDJ400 no longer needs a keyboard or an ssh
session to be shut down or recovered.

- **Settings menu** — a cog in the top-right corner opens a centered panel
  with **POWER OFF**, **RESTART MIXXX** and **BACK** (`system-menu.patch`,
  patch 12). Both actions are tap-again-to-confirm: the first press flips
  the button to a red "TAP AGAIN TO …" face, the second commits. Arming one
  option disarms the other, BACK and the cog clear it, and a 5 s timer
  disarms both, so a menu left open mid-set never leaves a live one-tap kill
  on screen. The panel is modal — taps outside it are swallowed rather than
  reaching a deck control by accident — but playback is untouched while it
  is open. Power off goes through `systemctl poweroff`, falling back to the
  same passwordless sudo the USB eject already uses; if every route is
  refused a POWER OFF FAILED banner says so instead of leaving a dead button.
- **Hold-to-restart** — hold either on-screen **LOAD** button (Browse or
  Search tab) for **7 s** to kill and relaunch Mixxx (`hold-to-restart.patch`,
  patch 11). The button blinks faster and faster while held (same
  accelerating flash as the USB eject hold), a centered **RESTARTING MIXXX…**
  banner confirms the trigger, then a detached helper runs `killall mixxx`
  (SIGTERM first for a clean library flush, `killall -9` after 10 s if it
  won't die) and relaunches Mixxx with the same binary and arguments it was
  started with (`DISPLAY=:0` exported if unset). Releasing before 7 s
  cancels; short taps still load the selected track exactly as before. This
  is the recovery gesture — the settings menu is the one to hand to someone
  else using the deck; both share a single implementation.
- **Headphone cue is much louder** — the cue/PFL gain ceiling goes from
  +14 dB to +30 dB (`headphone-gain-ceiling.patch`, patch 10). The DDJ-400
  cue out maxed out far too quiet on the Pi; a bypass tone straight to the
  hardware proved ~20 dB of clean headroom the old stage could not reach.
  Audio-taper pot, so unity stays at knob centre — only the top extends. If
  you re-map the physical HEADPHONES LEVEL knob to `headGain`, scale it to
  the new x31.6 max.

Also fixes CI: `publish-release.yml` had drifted to applying only 9 of the
patches, so releases cut from it would have shipped without the headphone
gain ceiling or hold-to-restart. Both workflows now apply the full series.

**Limitation:** both restart routes are triggered from inside Mixxx, so they
recover *soft* failures (audio dead, controller wedged, UI misbehaving but
still responding to touch). If the UI event loop is completely frozen
neither can fire — that case still needs a power cycle.

## Install (on the Pi)

```
sudo ./update-pioneered.sh
```

## Field checks

1. Cog appears top-right; the three tabs keep their normal width. Tapping
   it opens the settings panel; BACK closes it.
2. With the panel open, taps outside it do nothing (no deck reacts).
3. Tap RESTART MIXXX once → red "TAP AGAIN TO RESTART"; wait 5 s → it
   disarms itself. Tap twice → Mixxx quits and relaunches.
4. Tap POWER OFF twice → the Pi shuts down cleanly (no ssh needed).
5. Arm POWER OFF, then tap RESTART MIXXX: the power button disarms.
6. Browse tab, tap LOAD 1 / LOAD 2 briefly: track loads as before, no
   flicker on the button.
7. Hold LOAD 1: after ~0.6 s it starts blinking, accelerating; release at
   ~3 s → nothing happens. Hold LOAD 2 a full 7 s → RESTARTING MIXXX…
   banner, then Mixxx relaunches (fullscreen, correct skin, USB re-detected).
8. Hold-to-eject on USB A/B still behaves as in r20 (banner at 5 s, force
   at 10 s).
9. Headphone cue: with the DDJ-400 HEADPHONES LEVEL up, cue level is
   usably loud and clean; knob centre still sounds like unity.
