# v2.5.0-r25 — jog wheel nudge fixes

<!-- debs: rebuild -->

New Mixxx build. Two fixes to how the DDJ-400 jog wheel nudges a playing
track — nothing else changes.

- **Nudging the side no longer scratches the track.** Turning the side ring is
  a pitch bend and only ever a pitch bend now. Before, the mapping decided
  scratch-vs-bend from a deck flag (`scratch2_enable`) instead of from which
  part of the wheel you touched, so any nudge landing while that flag was still
  set grabbed the platter and stopped the track. The flag lingers after you let
  go of the platter top — Mixxx eases the rate back to playback speed before
  clearing it — and every nudge during that window restarted the ramp and kept
  it open, which is why it cleared up after a few seconds of leaving the wheel
  alone. Scratching now requires the platter top's touch sensor to actually
  report your hand on it (`jog-nudge.patch`, patch 16).
- **The nudge follows your hand instead of lagging behind it.** Mixxx smoothed
  the nudge over a fixed count of 25 audio buffers, so on the Pi's buffer size
  that was more than half a second of averaging — the pitch change arrived
  late and kept arriving after you stopped turning, so every beatmatch
  overcorrected. The smoothing window is now a fixed ~60 ms of real time
  whatever the audio buffer is set to, and the nudge stops when your hand
  stops.
- **A nudge shifts the track by the same amount at any latency.** The
  per-detent effect used to scale with the audio buffer setting, so changing
  the buffer silently changed the feel of the wheel. It is normalised now.
- Overall the nudge is **less sensitive** than before: the mapping's
  `bendScale` halves from `0.8` to `0.4`, so a small turn moves the track less.

Touching the **top** of the platter still stops and scratches the deck exactly
as before, and SHIFT + platter still fast-seeks.

**Tuning the sensitivity** (for future tweaks): `bendScale` near the top of
`res/controllers/Pioneer-DDJ-400-script.js` is the one number that sets how far
one detent shifts the track — raise it for coarser nudges, lower it for finer
ones. It is plain JavaScript, so it can be edited on the Pi (under
`/usr/share/mixxx/controllers/`) and picked up by restarting Mixxx, with no
rebuild. The smoothing window and the latency normalisation are named constants
in `mixxx-patch/jog-nudge.patch`: `kJogFilterWindowSeconds` (0.06) and
`kJogReferenceBufferSeconds`.

## Install (on the Pi)

```
sudo ./update-pioneered.sh
```

## Field checks

1. Start a track and, within the first second, nudge the **side** of the jog
   wheel forward and back: the track speeds up and slows down smoothly and
   keeps playing. It must never grab, stop or scratch.
2. Do the same immediately after lifting your hand off the platter top — the
   nudge takes effect right away rather than being ignored.
3. Beatmatch a track that is out of time: the pitch change follows your hand
   and stops when your hand stops, with no lingering drift to correct back.
   One nudge should get you close instead of overshooting.
4. Check the sensitivity feels right for a small rotation; if it is still too
   coarse (or now too fine), retune `bendScale` as described above.
5. Touch the **top** of the platter while playing: the track still stops and
   scratches, and releasing it resumes at playback speed.
6. SHIFT + platter still fast-seeks through the track.
7. With a loop active, the loop-in / loop-out adjust from the platter still
   works — including letting go of the platter part-way through an adjust.

If step 1 still misbehaves, run Mixxx with `--controllerDebug` and watch the
log while nudging the side. It prints every incoming MIDI message, which shows
whether the side ring reports as CC `0x21`/`0x23` and whether the platter's
capacitive touch sensor is firing note `0x36` on its own — a false touch would
point at grounding on the Pi's power/audio path rather than at software.
